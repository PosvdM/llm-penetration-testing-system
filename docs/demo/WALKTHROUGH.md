# 演示指南

[返回项目首页](../../README.md) · [文档目录](../README.md)

本指南说明如何展示项目流程，不提供预设漏洞成绩，也不将模拟报告作为实测案例。

## 只查看控制台

1. 按[安装与配置](../setup/GETTING_STARTED.md)启动前后端。
2. 打开 <http://127.0.0.1:5173>，查看后端状态、任务列表和工作流区域。
3. 空任务仓库会初始化一个指向 `http://127.0.0.1:8080` 的演示任务。任务名称只是场景标签，系统不会安装或启动相应靶场，也不代表检测能力已在该场景得到验证。
4. 选中任务查看阶段与工具计划。**不点击自动运行或手动推进，就不会执行任务中的扫描步骤。**

适合首次浏览者的观察顺序：任务入口 → 工作流时间线 → 工具计划 → LLM 策略 → 验证结果 → 报告。

## 在授权本地靶场运行

### 运行前

- 准备自己控制的隔离靶场，确认目标地址、测试授权和可接受的探测范围。
- 安装需要的外部工具，确认 ProjectDiscovery httpx 没有与 Python 同名命令混淆。
- 需要真实模型分析时配置 `.env`；不配置密钥则使用规则策略。
- 确认没有无关服务占用靶场端口。不使用公网随机地址作为演示目标。

### 操作步骤

1. 在控制台创建任务，填写靶场地址和能识别本次测试的场景名称。
2. 查看计划中的工具与执行模式。真实验证应确认依赖已安装，不能以模拟输出替代检测结果。
3. 选择自动运行，或逐阶段手动推进。自动运行期间不能手动推进。
4. 在时间线中查看阶段记录，在详情中查看模型策略、推荐工具、重点路径与结果摘要。耗时阶段可能让状态请求等待。
5. 流程进入 `REPORTING` 后查看 Markdown 报告预览；原始文件位于 `data/reports/<task-id>/`，工具日志位于 `data/raw/<task-id>/`。

## 如何解释结果

| 展示内容 | 可以说明什么 | 不能据此推断什么 |
| --- | --- | --- |
| `COMPLETED` | 编排流程结束 | 所有工具成功、真实模型被调用或目标安全 |
| 工具 `success=true` | 适配器按自身标准执行成功 | 一定发现可利用漏洞 |
| `execution_mode=native` | 调用了真实工具或内置模块 | 工具输出一定正确、检测覆盖完整 |
| `execution_mode=simulated` | 使用了模拟输出 | 对目标完成了真实验证 |
| `verification_status=verified` | 命中了项目中的确认规则 | 一定是漏洞；也可能是攻击面信息 |
| 没有漏洞发现 | 当前流程未确认漏洞 | 不存在未覆盖或需人工验证的问题 |

报告的工具执行摘要包含执行模式。只要存在参与结论的模拟证据，就应将报告标记为流程演示材料，而不是实测成果。

## 展示材料建议

可以截取真实运行后的控制台全景、结构化策略、工具结果和报告预览；分享前遮盖密钥、非公开目标、敏感响应内容与个人路径。保留原始证据供自己复核，不把未脱敏产物提交到仓库。

如果需要报告运行耗时、发现数量或检测效果，应同时记录靶场版本、工具版本、模型配置、执行模式和人工复核结果。本仓库不预填这些指标。
